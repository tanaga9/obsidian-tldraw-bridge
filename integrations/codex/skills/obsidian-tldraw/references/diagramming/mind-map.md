# Mind maps

For a new mind map, use a Buzan-style radiant map by default. Its central image
and branches help readers explore and remember associations around one topic.
Honor an explicit request for another style. Use a tree diagram, radial if
useful, when the task calls for boxed nodes and a formal hierarchy. Use a
concept map when named relationships and cross-links are the main point.
Preserve the conventions of an existing map for local edits. Apply a Buzan
redesign when the user requests that structural change.

## Plan the radiant structure

The paper method develops associations as the person draws. For an exploratory
map, use what the user has shared, propose associations as ideas, and let the
branches evolve as connections emerge. For a map of supplied material, derive
branches from that material and preserve its meaning. Keep any added ideas
clearly distinguishable from source facts when the distinction matters.

- Start with a topic-specific image near the visual center. Leave room for
  branches to grow around it. Let the subject determine branch count and depth.
- Give each branch one keyword or key image as its primary cue. Use one
  word when it conveys the idea in the requested language. Keep proper names
  and established terms such as “mind map” together when they name a single
  concept. Put explanatory prose in supporting Markdown or an annotation.

## Choose the illustrations

Reuse a suitable illustration or draw a simple motif with native shapes.
Use ImageGen when an original illustration would make the topic or an
association clearer. Generate the central image or a branch illustration
as a separate, text-free asset with a background that leaves the branch
roots visible. Follow the [image insertion workflow](../operations.md#image-insertion).
Use a native motif if the generated asset is unavailable or unusable.
Keep titles, branch strokes, and labels editable in tldraw.

## Draw the branches

- Grow organic curves directly from the central image. Branch out from the
  outer end of each parent to form a visible fork. Make main branches thickest
  at the center and taper them outward. Use progressively thinner strokes at
  deeper levels.
- Give each main branch a distinct color and carry it into its descendants.
  Match keyword colors to their branches where contrast permits.
- Set each keyword in clear lettering along and just above its own branch.
  Shape the branch around the label. Give the word or key image a supporting
  section about as long as its visible span. Use larger or bolder lettering
  for main ideas and smaller lettering for detail.
- Use a distinct mark for a meaningful cross-branch association so it is easy
  to tell from a fork.

## Build it in tldraw

- Use [editable freehand strokes](../freehand.md). A closed, filled outline can
  form a tapered main branch. Set the child path's start at the visible fork
  in the same coordinate space. If exact tapering is impractical, vary stroke
  weight between levels.
- Give rotated keyword shapes enough width to stay on one line. Adjust the
  fork, descendant starts, and labels together when reshaping a branch.

## Verify the rendered map

For Buzan-style creation, redesign, or conformance review, supplement the
[shared quality check](index.md#quality-check) at the intended display size:

- The central image anchors the topic and the main branches visibly grow from it.
- Branch families are traceable through their forks, color, and decreasing weight.
- Each keyword or key image is supported by its branch, with little unused line
  beyond it and no collision with the junction.

A boxed radial hierarchy calls for structural revision when the deliverable
is a Buzan-style mind map. During a review, report issues in the requested
scope. For local edits, verify the affected branch in the existing style.
