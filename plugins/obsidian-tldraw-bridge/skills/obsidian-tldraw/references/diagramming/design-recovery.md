# Recover a stalled diagram design

Use when the initial structure cannot be chosen, or revisions stop helping the
next design decision. This is an agent procedure, not an automatic detector.

## When to switch

Use recovery when the agent cannot connect the next structural change to a
specific reader problem and a result to check, or when repeated revisions leave
the same problem without a new finding. For example, two layouts still leave
several equally plausible starting points and no cue for the intended order.

Continue a known correction normally. Choose routinely between equally suitable
layouts. Retrieve missing source facts or ask about a consequential reader goal
before experimenting; layout trials cannot supply those facts. SDK and saving
failures use [operation recovery](../operations.md#results-and-failure-recovery).

## Make one small trial

Identify one uncertainty, a hypothesis, and what observation would decide the
next step. Choose the smallest useful action; do not perform the whole table.

| Uncertainty | Action |
| --- | --- |
| The reader's goal is unclear. | Ask an intuitive outcome choice, such as "See who does what, or follow what happens first?" Reuse any established answer. |
| The content is too abstract. | Draw one source-backed case from its starting event to its outcome. Check other required cases before generalizing. |
| The overall structure is unclear. | Draw the core relationship with only a few elements, often 3–5. Add detail once the core answers the reader's question. |
| Two organizing principles are plausible. | Draw two small views of the same essential facts, such as time order versus responsibilities. Compare them against the reader's task. |
| The cause of difficulty is unclear. | Change one plausible factor in a copy of the affected region and compare before/after at the same viewing size. |

For example, test whether ownership grouping hides the sequence by drawing one
request path in time order, retaining its events and owner labels. Before drawing,
choose the check: can the start and next event be identified without backtracking?
A prettier result alone does not answer that question.

Produce and inspect an actual sketch through the bridge workflow. Preserve the
current usable diagram, required relationships, and relevant qualifications;
limit the trial's scope rather than stripping essential meaning. Follow
[improvement conversations](improvement-patterns.md) for intuitive questions,
comparison choices, and editing scope. Keep trials that change the main structure
in separate drafts. Recovery and successful trials do not authorize applying a
structural redesign; follow the [redesign scope conditions](improvement-patterns.md#ordinary-improvement-and-structural-redesign)
before replacing the delivered diagram. No separate trial report is needed.

## Use the result

Compare the result with the observation chosen before the trial:

- **Supported:** the expected effect is visible and the required relationships
  remain intact. Use that finding to choose the next structural step.
- **Rejected:** a valid trial does not produce the expected effect. Use what it
  rules out to choose another hypothesis.
- **Inconclusive:** the available view, facts, or reader response cannot decide.
  Repair clipped text or missing relationships before judging the hypothesis;
  a broken sketch is not evidence against its organizing principle.

Use actual reader feedback for claims about that reader's understanding or
preference; the agent's own inspection establishes only what it checked.

After two inspected trials of the same uncertainty yield no useful finding,
stop making variants and ask for the missing concrete choice, fact, or example.
Count inspected sketches, not API calls or export retries; an informative
rejection is progress. Rephrasing or a new turn does not reset the same impasse.
Allow "neither," combinations, and "not sure"; wait for a required answer.
If no answer could distinguish otherwise acceptable choices, choose routinely.
Report a remaining limitation when the required evidence is unavailable.

Resume the [production workflow](index.md#production-workflow) when the trial
result or answer supports a next change serving the reader's task. Integrate
useful findings into a coherent structure, then check the full required content,
refine, verify saving, and deliver. Clean up unused drafts when cleanup is in scope.
